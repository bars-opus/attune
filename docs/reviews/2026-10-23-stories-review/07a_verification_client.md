# 07a — Adversarial verification: Critical and High findings in 01 posting, 02 watching and 03 rings

Verifier A · 2026-10-23 · read-only. I wrote and ran probes only from the scratchpad (`…/scratchpad/verify_a/`: `reel_verify_test.dart`, `ring_tap_verify_test.dart`, `outbox_verify_test.dart`). Every probe drives the real widgets, providers and controller, with fake gateways. No probe was copied under `test/`: `git status --porcelain test/` shows only the user's own earlier edits. I edited no repo file and ran no SQL; nothing here needed the database.

Method: for each Critical or High finding I opened the cited lines, traced the path, and looked for a guard elsewhere, an unreachable branch, a wrong line, an earlier fix or a misread API. I built a behavioural probe wherever a widget or the controller could reproduce the finding. Severity was re-graded by its effect on a real person, using the BRIEF's scale. Rows from 04, 05 and 06 that describe the same defect are merged in.

## 2. Root-cause groups (the smallest set of fixes that clears the confirmed items)

- **A. Track the playing item by id, not by index** (V1, V2, 02#16; makes V9 safe). Keep `_currentItem` set in `_startItemAsync`. On each new list, re-derive the index with `indexWhere(id)`, and start a new item when the current one is gone or the list is empty. Delete, Reply and Remove-from-map act on `_currentItem`. Step off immediately after a delete. The ticker and `onEnded` read the live list.
- **B. Keep data on screen during a refresh** (V3). In `_KeysetPager.refresh()`, after the first load, use `AsyncLoading().copyWithPrevious(state)`, or leave `state` alone until the page arrives. Show the full-screen spinner only before the first data.
- **C. Make item completion and close one-shot** (V4, 02#13, #14, #23). Cancel `_tickTimer` when an item completes. Add a `_closing` latch that bumps the generation, pauses the player and pops only if `ModalRoute.isCurrent`. Add a modal pause cause around each dialog.
- **D. A real per-item load state machine** (V5, V6, 02#15). Start item 0 exactly once. Count an item as rendered on its first decoded frame (an `ImageStreamListener`, or video init), and only then start the clock and mark it viewed. On failure, show "Couldn't load, tap to retry" with a bounded backoff.
- **E. Key caches by storage key and reuse a URL within the screen and its TTL** (V7; also 03-M4, 04#6, 06#16). Keep a screen-local `{itemId: (url, mintedAt)}` map, and use `cacheKey: storageKey` for thumbnails. This needs a one-line spec amendment to "never cached".
- **F. Owner decision: resume at the first unseen item, and fade viewed segments** (V8).
- **G. Owner actions: a review step before posting, and Delete in the own reel** (V17, V9). Ship G only after A.
- **H. Ring hit geometry** (V10). Move the 48 dp `+` hit box outside the thumbnail circle, and test with both callbacks wired.
- **I. Make the outbox as resilient as chat's** (V11, V12, V13). Network and RATE_LIMITED never count toward the cap. Flush on reconnect and on resume. Classify `StorageException` by status (RLS → re-mint and re-queue; 409 on my own unconsumed key → finalize; 413/MIME → permanent; missing file → `media_missing`). Re-mint near expiry. Upload through `ChatMediaUploader` (abort on stall, progress).
- **J. Capture duration boundary** (V14). Add tolerance or a `trimEnd: 60 s` clamp in prepare, and report `min(actual, 60000)`. This file is shared with streaks, so test both flows.
- **K. Shared camera configuration** (V15, V16). Make the resolution preset an embedder parameter (stories `veryHigh`, streaks unchanged). If audio is denied, initialise again without audio. Let the embedder supply the error copy, and add Close and Open Settings. This touches the shared streak camera and is a regression risk: keep `capture_camera_test` and `streak_camera_contract_test` green.

## 3. Mediums that should be upgraded

- **02#12 → High.** Focusing the composer and holding the photo share one pause flag, and a tap on the photo navigates. In Flutter 3.29, `EditableText`'s default tap-outside action does **not** unfocus for touch on iOS or Android (`editable_text.dart:7030-7038`). So a person who taps the photo to dismiss the keyboard moves to the next story instead. The keyboard stays open, and `_startItem` clears `_heldPaused` (`story_reel_screen.dart:417`) while focus remains. The reel then **auto-advances every 5 s while they type**, and Send quotes whichever story is current. That is the same misdirected reply as V2, reached through a very common gesture. Fix it with group A plus a separate composer pause flag; a tap on the photo while composing should only unfocus.
- No other Mediums in 01, 02 or 03 are clearly underrated. 01#14 (closing the camera during the slow place lookup loses the take) is a borderline case. It stays Medium because the person chose to close, but it should land with group G's review step, which removes the window.
